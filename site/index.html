How it works

Deterministic math, generative narrative

The model never sees raw prices or the internet. Python computes the indicators; Claude only turns that small, auditable snapshot into words.

TelegramUser sends a ticker
→
FastAPI + botAccess gates, rate limits
→
Market layeryfinance → RSI, SMA, volatility, volume
→
Claude APIReasons only over the JSON snapshot
→
ReplyCard + grounded analysis

Grounded by design

Every claim in the analysis traces back to a field in the snapshot. Prompts are small, cheap and can't invent news, earnings or price targets.

Stances from rules, not the LLM

Buy / Hold / Sell comes from fixed, unit-tested conditions, so every stance can be explained. Claude describes the setup and never prescribes trades.

Graceful degradation

If Claude is down or the daily AI budget is used up, users still get the full indicator card instantly.

How the score is built

Signals: price vs. SMA 200, stacked averages, RSI extremes, 3-month momentum, distance from the 52-week high, heavy volume. Each bullish signal counts +1, each bearish −1, and every 2 net points move the score one step from a neutral 3, since the trend signals overlap.

Security

Built assuming hostile users

The bot is open to anyone on Telegram and the server has a public URL. Every defense is covered by tests, and an independent security review's findings are fixed.

✓Strangers running up the AI bill

Claude is called only for an allowlist of users, checked before a global daily cap, plus a hard monthly spend limit.

✓Forged Telegram updates

Webhook secret compared in constant time; the app refuses to start with a placeholder or short secret.

✓Editing the watchlist or abusing the API

The dashboard is read-only for visitors; edits and the raw API need the owner's password. API docs off in production.

✓Malicious sites using the owner's browser

A custom request header blocks CSRF; a localhost-only Host check blocks DNS rebinding.

✓XSS and injection

Escaped output, textContent-only rendering, a hash-based CSP, parameterized SQL, strict ticker validation.

✓Flooding the bot or server

Per-user rate limits, concurrent update handling, capped Yahoo fetches, request size limits, bounded caches.

✓Leaking secrets

Secrets only in env vars, kept out of git and images; logging that would expose the bot token is silenced.

✓Supply chain

Non-root container, read-only CI token, pip-audit on every push, weekly Dependabot updates.
